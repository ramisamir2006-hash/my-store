# كاراس و أبو سيفين — نظام المبيعات والمخزون (ويب + تطبيقات)

نظام واحد بثلاثة تطبيقات تعمل على الموبايل والكمبيوتر من المتصفح (ويمكن تثبيتها على الشاشة الرئيسية):

| الرابط | لمن | ماذا يفعل |
|---|---|---|
| `/shop/` | العملاء | تصفح المنتجات، سلة، طلب، دفع (عند الاستلام / تحويل / فيزا)، متابعة الطلبات |
| `/staff/` | الموظفون | طلب جديد (مسح باركود)، العملاء + الخصومات، الطلبات، عرض المنتجات (بدون سعر الشراء) |
| `/manager/` | المدير | كل ما سبق + إضافة المنتجات والصور، المخزون، التقارير والأرباح، الموظفون، الإعدادات، النسخ الاحتياطي |

## أهم المزايا
- **حسابات منفصلة** للمدير والموظفين والعملاء، والموظف لا يرى سعر الشراء ولا التقارير.
- **كود فريد لكل منتج** (مثل `KS-RG-0001`) + باركود (مسح بالكاميرا أو قارئ باركود) + طباعة ملصقات.
- **ثلاث أسعار:** جملة / نص جملة / قطاعي + **سعر الشراء** الأصلي وهامش الربح.
- **خصم خاص لكل عميل بنسبة %** يضعه المدير أو الموظف (والمدير يحدد أقصى خصم للموظف).
- مخزون بالحركات (استلام / تالف / جرد / بيع / إلغاء)، تنبيه النواقص، قيمة المخزون.
- دفع: **عند الاستلام**، **تحويل بنكي / محفظة / إنستاباي** (العميل يرفع صورة الإيصال والمتجر يؤكد)، و**فيزا عبر Paymob**.

## الرفع على سيرفر VPS (خطوة بخطوة)

### 1) ما تحتاج شراءه
1. **VPS** بنظام **Ubuntu 24.04** (مثل Hetzner أو DigitalOcean أو Contabo أو Hostinger). يكفي 1 CPU و 1–2 GB رام. اختر أقرب منطقة لمصر (أوروبا). سيعطونك **عنوان IP** وكلمة سر root.
2. **اسم نطاق (دومين)** مثل `karas-shop.com` (من Namecheap أو GoDaddy أو Cloudflare أو Hostinger). *الدومين ضروري:* بدونه لا يعمل HTTPS، وبدون HTTPS لا تعمل كاميرا الباركود على الموبايل ولا تثبيت التطبيق ولا بوابة الفيزا.

### 2) ربط الدومين بالسيرفر
في لوحة الدومين أضف سجل **A**: الاسم `@` → قيمته IP السيرفر. (وسجل ثاني `www` بنفس الـ IP إن أردت). قد يستغرق دقائق إلى ساعات.

### 3) رفع الملفات (من جهازك)
في Windows PowerShell (أو Terminal على ماك) من مجلد الملف:
```
scp karas-system.zip root@IP_السيرفر:/root/
ssh root@IP_السيرفر
```

### 4) على السيرفر
```
apt-get install -y unzip
unzip karas-system.zip && cd karas-system
bash deploy/setup-vps.sh        # يثبّت Docker والجدار الناري والنسخ الاحتياطي اليومي
nano .env                       # اكتب DOMAIN= اسم الدومين (ومفاتيح Paymob إن وُجدت)
docker compose up -d --build    # تشغيل النظام + شهادة HTTPS تلقائية
```
بعد دقيقة افتح `https://الدومين/manager/` — أول شاشة تطلب إنشاء **حساب المدير**. ثم:
1. **الإعدادات**: بيانات التحويل البنكي، أقصى خصم للموظف، الشحن، الأقسام.
2. **المنتجات → منتج جديد**: الاسم، الأسعار الثلاثة، سعر الشراء، الكمية، الصور، الباركود.
3. **الموظفون**: أنشئ حساب لكل موظف، وأعطِهم رابط `/staff/`.
4. أعطِ العملاء رابط `/shop/`.

### التحديث لاحقاً
ارفع ملف zip الجديد وفكّه فوق القديم (لا تحذف `.env`) ثم `docker compose up -d --build`. **البيانات محفوظة** في وحدة تخزين Docker ولا تُمسح.

## تفعيل الدفع بالفيزا (Paymob)
1. افتح حساب تاجر في **Paymob (مصر)** وأكمل التوثيق. ابدأ بـ **وضع التجربة (Test)** قبل الإنتاج.
2. من لوحة Paymob (أسماء القوائم قد تختلف قليلاً) خذ:
   - **API Key**
   - **Integration ID** (تكامل بطاقات Online Card)
   - **iframe ID**
   - **HMAC secret**
3. ضعها في `.env`:
   ```
   PAYMOB_API_KEY=...
   PAYMOB_INTEGRATION_ID=...
   PAYMOB_IFRAME_ID=...
   PAYMOB_HMAC=...
   ```
4. في إعدادات التكامل داخل Paymob اضبط:
   - **Transaction processed callback:** `https://الدومين/api/paymob/callback`
   - **Transaction response callback:** `https://الدومين/shop/`
5. `docker compose up -d` ثم جرّب بطاقة الاختبار من Paymob على طلب تجريبي. يجب أن يتحول الطلب إلى **مدفوع** تلقائياً.

**الأمان:** بيانات البطاقة تُكتب في صفحة Paymob فقط ولا تمر بسيرفرك. الطلب لا يُعتبر «مدفوعاً» إلا بعد رد Paymob الموقّع (HMAC) ومطابقة المبلغ — وليس بمجرد رجوع العميل للموقع.

## التحويل البنكي
من **الإعدادات → طرق الدفع** اكتب البنك واسم الحساب والرقم والمحفظة وإنستاباي. عند اختيار العميل «تحويل» تظهر له هذه البيانات ويرفع صورة الإيصال/رقم العملية، فيظهر لك ولموظفيك داخل الطلب، وتضغط **«تحديد كمدفوع»** بعد التأكد من وصول المبلغ.

## النسخ الاحتياطي (مهم)
- يتم **نسخ يومي تلقائي** الساعة 3:30 داخل السيرفر (آخر 14 يوم).
- لكن إذا حُذف السيرفر تضيع النسخ معه، لذلك **حمّل نسخة بنفسك أسبوعياً** من **الإعدادات → تحميل نسخة احتياطية** (قاعدة البيانات)، وأخرى لصور المنتجات عند الحاجة.
- الأوامر المفيدة: `docker compose logs -f app` (سجل الأخطاء)، `docker compose restart`، `docker compose ps`.

## تشغيل تجريبي على جهازك (بدون دومين)
تحتاج Node.js 22.13 أو أحدث:
```
node server/index.js     # ثم افتح http://localhost:3000
npm test                 # اختبارات الصلاحيات والأسعار والمخزون والدفع
```
(على الجهاز يعمل كل شيء ما عدا كاميرا الباركود على الموبايل والتثبيت — يحتاجان HTTPS.)

## حدود يجب معرفتها
- **الواجهة بالعربية فقط حالياً** (يمكن إضافة الإنجليزية/الفرنسية/الإيطالية/الصينية لاحقاً).
- ربط **Paymob** مكتوب حسب توثيقهم لكنه **لم يُجرَّب على حساب حقيقي** — جرّبه في وضع Test أولاً.
- لا يوجد ربط شركات شحن؛ حالة الشحن تُحدَّث يدوياً.
- مسح الباركود بالكاميرا يعمل على أندرويد وكروم/إيدج؛ **الآيفون** يحتاج قارئ باركود بلوتوث، أو ملف `html5-qrcode.min.js` اختياري في `public/shared/vendor/`.
- قاعدة البيانات SQLite على سيرفر واحد — مناسبة لمتجر بحجمك (آلاف المنتجات والطلبات)، وليست لعشرات الآلاف من الزوار في نفس الوقت.
